# Fontes de Informação

A definição dos requisitos do **MKpause** utiliza diferentes fontes de informação para compreender o contexto do problema, identificar necessidades dos usuários e orientar as funcionalidades propostas para a plataforma.

A utilização de múltiplas fontes permite analisar o problema sob diferentes perspectivas e reduzir a dependência de uma única fonte durante o levantamento de requisitos.

---

# 📚 Pesquisa Bibliográfica e Documental

Pesquisas bibliográficas e documentais são utilizadas para compreender conceitos relacionados à:

- autorregulação;
- bem-estar no ambiente escolar;
- saúde emocional de adolescentes;
- acompanhamento de estudantes;
- acessibilidade;
- privacidade e proteção de dados.

Essas pesquisas auxiliam principalmente na compreensão do domínio no qual o MKpause está inserido e na identificação de cuidados necessários durante o desenvolvimento da solução.

## Contribuição para o projeto

A pesquisa documental auxilia na definição de:

- contexto do problema;
- limites da plataforma;
- cuidados relacionados às informações dos estudantes;
- características das atividades de autorregulação;
- requisitos não funcionais;
- critérios de acessibilidade e privacidade.

---

# 👥 Usuários e Stakeholders

As necessidades dos diferentes usuários envolvidos no processo constituem uma das principais fontes para definição das funcionalidades.

Os principais grupos considerados são:

- estudantes;
- professores;
- psicólogos escolares;
- psicólogos clínicos;
- responsáveis;
- administradores da plataforma.

## Contribuição para o projeto

A análise das necessidades desses usuários auxilia na definição de:

- funcionalidades disponíveis para cada perfil;
- permissões de acesso;
- formas de acompanhamento;
- registros necessários;
- alertas;
- observações;
- vínculos entre estudantes e profissionais;
- informações necessárias para utilização da plataforma.

---

# 🗣️ Levantamento com Potenciais Usuários

O contato com potenciais usuários e pessoas relacionadas ao contexto escolar pode ser utilizado para compreender dificuldades, necessidades e expectativas relacionadas ao problema abordado.

Entre as técnicas de elicitação aplicáveis ao projeto estão:

- entrevistas;
- questionários;
- observação;
- conversas exploratórias;
- análise de cenários de uso.

## Contribuição para o projeto

Essas técnicas podem auxiliar na identificação de:

- situações em que estudantes necessitam de uma pausa;
- dificuldades existentes no processo atual;
- recursos considerados úteis pelos estudantes;
- necessidades dos profissionais responsáveis pelo acompanhamento;
- informações relevantes durante uma situação de alerta;
- expectativas relacionadas à facilidade de uso da plataforma.

---

# 🔎 Análise de Soluções Existentes

A análise de produtos e plataformas relacionadas ao domínio permite observar como problemas semelhantes são tratados em outras soluções.

Essa análise pode considerar:

- funcionalidades oferecidas;
- organização das interfaces;
- formas de interação;
- pontos positivos;
- limitações;
- avaliações realizadas por usuários.

## Contribuição para o projeto

A análise de soluções existentes auxilia na:

- identificação de funcionalidades recorrentes;
- descoberta de oportunidades de melhoria;
- definição de diferenciais;
- identificação de problemas de usabilidade;
- análise de padrões de interação;
- geração de novas ideias para o MKpause.

---

# 🎓 Contexto Acadêmico

O desenvolvimento do MKpause também é orientado pelas atividades, conteúdos e processos de modelagem utilizados durante o curso de **Engenharia de Software da PUCPR**.

As atividades acadêmicas contribuem para estruturar e documentar:

- levantamento de requisitos;
- requisitos funcionais;
- requisitos não funcionais;
- requisitos de dados;
- regras de negócio;
- casos de uso;
- modelagem conceitual;
- modelagem lógica;
- prototipação;
- documentação do sistema.

Feedbacks recebidos durante avaliações e apresentações também são utilizados para revisar e corrigir os artefatos do projeto.

---

# 🔄 Validação e Refinamento

Os requisitos do MKpause não são considerados informações imutáveis.

Durante o desenvolvimento, novas informações podem exigir:

- inclusão de requisitos;
- alteração de requisitos existentes;
- remoção de funcionalidades;
- alteração de regras de negócio;
- revisão de atores;
- revisão de relacionamentos;
- atualização da modelagem de dados.

Quando uma alteração for realizada, os documentos relacionados devem ser revisados para manter a consistência do projeto.
